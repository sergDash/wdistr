# Archinstall - Ответы для нашей системы

Эталон ответов при установке Arch через archinstall для тестовой сборочной
VM (2026-09-25). Цель — повторяемая установка без лишних вопросов; из этих
ответов впоследствии собирается преднастроенный конфиг.

## Ответы

- **Язык интерфейса** — не менять (English). Русский ломает интерфейс
  archinstall, см. «Проблема - archinstall: выбор языка и лишние вопросы».
- **Локаль** — `kb_layout: us` (решение 2026-09-26: не ставить ru по
  умолчанию — в консоли приходилось вручную добавлять переключалку; раскладки
  возьмёт на себя keyd при настройке профиля), `sys_lang: ru_RU.UTF-8`,
  `sys_enc: UTF-8`,
  консольный шрифт `ter-u16n` (прежде `Cyr_a8x16`, заменён 2026-10-14:
  кириллица в консоли).
- **Регион зеркал** — `wdistr` (прежде Russia; заменён 2026-10-14 —
  регионом назван наш закрытый список, см. карточку «Зеркала»).
- **Разбивка диска** — best-effort default, файловая система **btrfs**
  (решение 2026-10-09, прежде ext4), без отдельного `/home`, без
  шифрования (шифрование — «на улучшения»). Итог: два раздела —
  1 ГБ fat32 `/boot`, остальное btrfs `/`.
- **Swap** — archinstall поставил «on zram, zstd» по умолчанию; для нашей
  системы решено потом заменить на файловый swap размером в половину
  оперативной памяти (простота).
- **Загрузчик** — GRUB.
- **Ядро** — linux.
- **Hostname** — `arch` (решение 2026-10-09, прежде `archlinux`).
- **Пользователи** — root и `user`, для тестовой VM пароли `123`; `user` с
  правами sudo (группа `wheel`) и в группе `docker` (назначается
  custom_commands после установки — поле groups в creds архинсталл
  не применяет). Другие группы не нужны: для X/Wayland
  в современном Arch отдельных групп не требуется (video/audio/input
  раздаются через polkit/udev). Значения — только для тестовой VM, в релиз
  не переносить.
- **Профиль** — пропускать (профили archinstall — это server/desktop/minimal;
  наш ISO приносит свой набор, там выбор дублируется).
- **Приложения и пакеты pacman** — пропускать: набор программ определяется
  нашим списком пакетов, а не вопросами установщика.
- **Сеть** — NetworkManager (как в Linux Mint — меньше проблем).
- **Часовой пояс** — `Europe/Moscow` (решение 2026-10-10, прежде UTC).
- **NTP** — включить.

## Сохранённый конфиг

Файл — `install/archinstall-config.json` (валидный JSON, archinstall 4.4,
20 ключей верхнего уровня). Извлечён из `/var/log/archinstall/install.log`
установленной системы: сам файл «Save configuration» пережил только живую
среду и погиб при выключении (см. «Извлечение файлов с диска VirtualBox»).

Ограничения перед использованием в автоматизации (вариант Б):

- размеры и координаты разделов в самом конфиге привязаны к 64-ГБ диску
  тестовой VM; `setup` при запуске пересчитывает размер корневого раздела
  под фактический размер указанного диска (проверено 2026-10-08:
  64 ГиБ — совпадение с исходным конфигом, 500 ГиБ — пересчёт,
  5 ГиБ — отказ «слишком мал»);
- устройство захардкожено как `/dev/sda` (единственное вхождение в
  конфиге) — это путь «куда ставить»; `setup` подставляет диск из
  третьего аргумента. После установки система привязана по UUID: fstab и
  GRUB ищут разделы по UUID (проверено на сборочной), поэтому смена имени
  или места диска (`sda` → `sdb`) систему не убивает;
- паролей в конфиге нет: они живут отдельным файлом
  `install/archinstall-creds.json` (ключи `!password` / `!root-password` —
  archinstall хеширует их сам при чтении);
- пустые `packages`, `profile_config`, `services` — подтверждение, что
  установка шла без выбора программ.

## Безинтерактивный запуск (проверено 2026-09-26)

Установка прошла полностью без вопросов, финал лога — `Installation completed
without any errors`.

Доставка файлов в живую среду — HTTP-сервер на хосте (корень репозитория):

```bash
setsid nohup python3 -m http.server 8000 --directory <корень репозитория> \
    </dev/null >/tmp/httpd.log 2>&1 &
```

В живой среде гость видит хост по адресу `10.0.2.2`. Сначала проверка
(`--dry-run` скачивает файлы, собирает конфиг и выходит, не трогая диск):

```sh
archinstall --config-url http://10.0.2.2:8000/install/archinstall-config.json \
    --creds-url http://10.0.2.2:8000/install/archinstall-creds.json \
    --silent --dry-run
```

То же без `--dry-run` — реальная установка.

Подтверждённые факты из исходников archinstall 4.4/master:

- `--silent` действует только вместе с `--config` (без конфига игнорируется);
- конфиг и учётные данные принимаются и по URL (`--config-url`, `--creds-url`);
- пароли в creds-файле могут лежать открытым текстом (`!password`,
  `!root-password`) — хеширует их сам archinstall (yescrypt) при чтении.

## Установка одной короткой командой

В живой среде вместо длинной строки с тремя URL — одна:

```sh
curl -fsSL http://10.0.2.2:8000/install/go.sh | sh
```

Проверка без установки — та же, с `--dry-run`:

```sh
curl -fsSL http://10.0.2.2:8000/install/go.sh | sh -s -- --dry-run
```

`go.sh` (в `install/`) сам подставляет `--config-url`/`--creds-url`.
- Минимальный набор после установки: `sudo` входит (проверено — команды
  `sudo pacman` работают), `nano` **не входит** (проверено 2026-09-26) —
  поэтому `nano` добавлен в `packages` конфига.

## Установка командой setup (наш ISO)

В живой среде нашего ISO. Сначала — список дисков, есть два равных
способа: команда `disks` (обёртка над `lsblk`: какие диски есть, чем
заняты, где смонтированы) или запуск `setup` без аргументов — тогда под
справкой печатается тот же список:

```sh
disks            # то же самое: setup (без аргументов)
```

Затем установка — диск указывается явно:

```sh
setup <имя> <пароль> <диск>     # например: setup ivan 12345 /dev/sda
```

Без третьего аргумента `setup` не запускается: печатает справку и тот же
список дисков. Диск должен быть целым устройством, не разделом — проверка
от опечатки вида `/dev/sda1`. При запуске диск подставляется в копию
вшитого конфига, а размер корневого раздела пересчитывается под размер
диска (иначе разделы привязаны к 64-ГБ диску тестовой VM, см. «Сохранённый
конфиг» выше). Перед установкой зеркала проверяются на доступность
поймённо (HTTP-запрос за 4 с на каждое; опыт 2026-10-08: медленное
зеркало срывало pacstrap). Проба идёт 3 кругами с паузой 3 с —
однократная давала ложное «всё мертво» на кратковременной просадке
(опыт 2026-10-15). Если не ответило **ни одно** зеркало — установка
останавливается до archinstall (решение 2026-10-15: `--offline`
отключает самопроверку сети, без остановки pacstrap завис бы на
мёртвых зеркалах); если ответило хоть одно — установка идёт с полным
списком, недоступные не отсеиваются: archinstall в `--offline` берёт
Server-строки из локального mirrorlist, URL-ы конфига в закачке не
участвуют, а полный список самовосстанавливается посреди установки.

Пароль открытым текстом — осознанный выбор: живая среда одноразовая,
а открытый аргумент убирает опечатки скрытого ввода. Один пароль —
и для пользователя, и для root. Скрипт — `iso/airootfs/usr/local/bin/setup`
(генерирует creds и временный конфиг на лету, запускает archinstall).

Замечание: имя команды перекрывает `/usr/bin/install` из coreutils —
в живой среде это безопасно (одноразовое окружение), при желании
переименовать — правка одного файла в профиле.

`go.sh` остаётся запасным путём (и способом проверки на стоковой живой
среде через dev-сервер хоста).
