# Проблема - picom: другой композитный менеджер

Статус: **решено — вариант А** (2026-09-26): для XFCE остаётся композитор xfwm4, picom установлен, но не запускается. Picom сохраняется для будущего своего рабочего стола.

## Симптом

`picom -b` отвечает, что другой композитный менеджер уже запущен.

## Причина

xfwm4 — оконный менеджер XFCE — имеет **встроенный композитор**, включённый
по умолчанию. Композитор в X один: второй (picom) параллельно не запустить.
Конфликт не поломка, а пересечение двух способов сделать одно и то же.

## Варианты

- **А (проще):** оставить композитор xfwm4, picom не запускать. Ничего
  настраивать не нужно — работает уже сейчас. Picom остаётся установленным
  на будущее (для своего рабочего стола на его основе может понадобиться).
- **Б:** отключить композитор xfwm4: Системные настройки → Настройки
  оконного менеджера → Композитор → снять «Включить композицию отображения»
  — после этого `picom -b` запустится.

## Как выбрать

Сначала пожить с вариантом А и посмотреть на tearing (разрывы кадров).
Если разрывов нет — picom для XFCE не нужен вообще. Если есть — вариант Б.
Решение фиксируется в `AGENTS.md` рядом с пунктом про picom.

## Дополнение (2026-09-27): пакетный автозапуск ломал первый вход

Выяснилось при разборе проблемы «нет курсора»: пакет `picom` поставляет
**свой автозапуск** `/etc/xdg/autostart/picom.desktop` — picom запускается
при каждом входе в XFCE сам, без нашего ведома, и отбирает Composite у
xfwm4 («Another compositing manager is running» → «Failed to create new
session» → прозрачная панель, неотрисованные окна).

Вывод варианта А дополнен: мало «не запускать picom вручную» — нужно
удалять пакетный автозапуск. Фикс в профиле:
`rm -f /etc/xdg/autostart/picom.desktop` (custom_commands).
