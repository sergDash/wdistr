# Автоподключение внешних дисков

Как USB-диск становится набором файлов, какие способы монтирования есть в
Linux и что из этого есть в wdistr (факты — проверка 2026-09-30).

## Путь диска от включения до файла

```
USB-диск вставлен
  → ядро создаёт /dev/sdb, раздел /dev/sdb1, шлёт udev-событие
  → КТО-ТО выполняет mount (привилегированная операция)
  → точка монтирования, например /run/media/user/МЕТКА
  → программы видят файлы
```

Ядро само не монтирует. Вся суть автоматики — в вопросе: кто выполняет
mount, по какому сигналу и под чьими правами.

## Способы

### 1. fstab — постоянный диск при загрузке

Запись в `/etc/fstab` по UUID:

```
UUID=dba5f4a2-6e1d-46a5-855a-fc5fe574e4f3  /media/serg/4TB  ext4  defaults,nofail,x-systemd.automount  0  2
```

(Это UUID диска бэкапа с хоста — тот самый 4TB.)

- Монтируется при загрузке; `x-systemd.automount` — монтируется по первому
  обращению, пока никто не открыл — диск не крутится.
- **`nofail` обязателен для внешнего диска:** без него система ждёт диск при
  загрузке — не подключён → долгая пауза или падение загрузки.
- Точка монтирования должна существовать заранее (`mkdir -p`).
- Плюс: предсказуемо, без демонов, путь постоянен. Минус: запись вручную
  на каждый диск; «вонючку вставил» автоматом не подхватит.

Для `settings/setup.sh` это основной сценарий: путь `/media/serg/4TB`
совпадает с дефолтом скрипта — после fstab-записи ничего настраивать не надо.

### 2. udisks2 — mount по требованию, без root

Демон (DBus), выполняет mount/unmount от имени пользователя:

```
udisksctl mount -b /dev/sdb1
→ Mounted /dev/sdb1 at /run/media/serg/МЕТКА
```

- Запись в fstab не нужна, root не нужен (polkit решает, разрешено ли).
- **Сам udisks2 ничего не монтирует автоматически** — его задача выполнить
  mount, когда его попросят. Попросить могут: файловый менеджер, свой код
  (wmenu/wpanel), ручная команда.
- Состав: пакет `udisks2` + dbus + polkit. В wdistr dbus и polkit уже есть
  (firefox → dbus, lightdm → polkit, xfce4-session → polkit-gnome) —
  не хватает только самого `udisks2`.

### 3. gvfs — слой GIO для «полноценных» десктопов

Файловые менеджеры говорят не с udisks2 напрямую, а с GIO-абстракцией
(GVolume/GMount); её реализует gvfs, который внутри сам ходит в udisks2.
Только gvfs и даёт привычный automount «вставил — открылось».

- Зависимости gvfs: сам + udisks2 + fuse3 + dconf + libsecret + libsoup3...
- Для минимального рабочего стола (свой код) gvfs не нужен: у нас нет
  GNOME/GIO-программ, которые за него цепляются.

## Что в wdistr сейчас (факты от 2026-09-30)

- **Автоматического подключения дисков нет.** В составе установленной системы
  нет ни `gvfs`, ни `udisks2` — и никто их не тянет как зависимость
  (проверено по Depends у thunar, thunar-volman, xfce4-session, firefox,
  lightdm, network-manager-applet).
- `thunar-volman` входит в группу `xfce4`, но в его бинарнике монтирование
  сделано через GIO (`g_volume_mount`): без gvfs он монтировать не может.
- Уже есть и пригодится: **dbus** (firefox) и **polkit + polkit-gnome**
  (lightdm, xfce4-session).
- В live-среде ISO `udisks2` присутствует (зависимость `solid`) — но live
  не равна установленной системе.

## Варианты (решение за пользователем)

1. **Диск бэкапа — fstab + UUID + nofail.** Постоянный диск, задача
   `setup.sh` и rsync закрывается полностью, без новых демонов.
2. **Съёмные флешки — + `udisks2`.** Один пакет: mount без root по команде
   из программы (wmenu/wpanel) или вручную `udisksctl`. Для XFCE-автомата
   «вставилось и само открылось» потребуется ещё и gvfs.
3. **Компромисс:** fstab для диска бэкапа + udisks2 для остального;
   gvfs не ставить (в составе минимального стола он лишний).

## Проверка

```sh
lsblk -f                    # устройство, ФС, UUID, где смонтировано
findmnt                     # что смонтировано сейчас
udisksctl status             # видит ли udisks2 устройства
udisksctl mount -b /dev/sdX1
```

## Открытые вопросы

- Согласовать состав: fstab-запись (и точку монтирования — держать
  `/media/serg/4TB` для совпадения с дефолтом setup.sh), ставить ли
  `udisks2`, нужен ли gvfs для XFCE-этапа.
- Испытание — после согласования, вместе с испытанием `settings/setup.sh`
  (подключить диск к тестовой VM).
