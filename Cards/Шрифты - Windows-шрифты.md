## Задача

Consolas и Segoe UI (пользователю подходит вариативная Segoe UI Variable)
должны быть и на рабочей машине, и в ISO дистрибутива. Локальные копии в
`~/.fonts/` не использовать — цель «поставил и работает» распространяется и
на шрифты.

## Почему не AUR-пакеты (перебрано 2026-10-11)

- `ttf-ms-win11` — PKGBUILD ждёт, что пользователь сам извлечёт шрифты из
  своей Windows-ISO и положит файлы рядом. Бюрократия без выигрыша.
- `ttf-ms-win11-auto` — стриминг eval-ISO через httpdirfs (FUSE) → loop →
  udisks. На нестабильной сети обрыв чтения install.wim оставляет httpdirfs
  смонтированным и loop прикреплённым; каждый следующий запуск yay стартует
  с `rm -rf $srcdir` и падает на ENOSYS («Функция не реализована») при
  удалении файла внутри FUSE-монтирования — кэш yay самоотравливается.
  Проверено на практике 2026-10-11: четыре безуспешных перезапуска подряд.
- `win11fonts-auto` — то же скачивание полного ISO (~6,2 ГиБ), но через
  makepkg как source: чудес той же механики, без возобновления закачки.

Вывод: пакет не нужен, нужна простая инструкция. Закачка одинакова во всех
вариантах (6,2 ГиБ с CDN Microsoft), отличается только обвязка — а обвязка
и ломается.

## Стабильная инструкция (однократно, повторяемо)

Эталон ISO (зафиксирован в PKGBUILD пакетов, sha256 проверен AUR):

- URL: `https://software-static.download.prss.microsoft.com/dbazure/888969d5-f34g-4e03-ac9d-1f9786c66749/26100.1742.240906-0331.ge_release_svc_refresh_CLIENTENTERPRISEEVAL_OEMRET_x64FRE_en-us.iso`
- sha256: `755a90d43e826a74b9e1932a34788b898e028272439b777e5593dee8d53622ae`

1. Скачать с возобновлением (повторять ту же команду при обрыве — wget
   продолжит с места обрыва). ISO лежит в корне репозитория, но в git не
   добавляется — имя закрыто в `.gitignore`:

```
wget -c -O win11-eval.iso "<URL выше>"
```

2. Проверить целостность (обязательно — качаем с прямого CDN, не из AUR):

```
echo "<sha256>  win11-eval.iso" | sha256sum -c -
```

3. Извлечь шрифты (нужен `7zip` — команда `7z`; в базовом наборе
   дистрибутива с 2026-10-11, вместе с `udftools`). Из ISO берётся
   `sources/install.wim`, из него — все файлы `Windows/Fonts`
   пачкой плюс лицензия:

```
mkdir -p /tmp/winf && cd /tmp/winf
7z e /home/serg/src/wdistr/win11-eval.iso sources/install.wim
7z e install.wim -y -o/tmp/winf/fonts \
  "Windows/Fonts/*.ttf" "Windows/Fonts/*.ttc" \
  "Windows/System32/Licenses/neutral/*/*/license.rtf"
```

4. Себе — в систему (не в `~/.fonts`):

```
sudo mkdir -p /usr/share/fonts/truetype/wdistr-win
sudo cp /tmp/winf/fonts/*.tt[fc] /usr/share/fonts/truetype/wdistr-win/
sudo fc-cache -f
```

Проверка: `fc-list | grep -i -E "consolas|segoe"`. Из `~/.fonts` убрать
папки `Consolas` и `SegoeUI` (и любые другие, чьи шрифты теперь системные).

5. В дистрибутив — те же файлы в `install/files/winfonts/` вместе с
   `license.rtf`; доставка в целевую систему — custom_commands по образцу
   курсоров mcMojave (tar или пофайловая отдача). Статус: файлы перенесены
   2026-10-11 (143 файла, 342 МиБ — весь набор образа), доставка не
   добавлена. Направление (решение 2026-10-11): base64 в custom_commands
   как механизм доставки признан некрасивым — 342 МиБ шрифтов в JSON
   archinstall не влезают разумно, и курсоры (3,2 МиБ) через base64 тоже
   пихать не хочется. Поискать другой путь доставки при подготовке
   следующей сборки ISO (варианты: свой пакет/репозиторий, отдача из
   живой среды, сжатый архив по-другому).

## Ограничение объёма

В git НЕ попадает ни сам ISO (6,2 ГиБ и это дистрибуция установочного
образа Windows), ни что-либо из него — имя `win11-eval.iso` закрыто в
`.gitignore`, лежит файл в корне репозитория. В git идут только
извлечённые ttf/ttc-файлы и license.rtf. После извлечения ISO остаётся в
корне репозитория для повторного использования — повторно качать не нужно.
