## Определить флешку

```sh
lsblk -o NAME,SIZE,TYPE,TRAN,MOUNTPOINT,MODEL
```

Смотреть на `TYPE=disk`, `TRAN=usb` и размер/модель. НЕ писать
образ на уже смонтированные диски с данными — назначение должно быть
очевидно (спасательная флешка, пустое устройство).

## Запись

Разделы флешки должны быть размонтированы, иначе dd упадёт с
«Device or resource busy»:

```sh
sudo umount /dev/sdX1 /dev/sdX2 2>/dev/null
sudo dd if=/путь/к/образ.iso of=/dev/sdX bs=4M status=progress conv=fsync
```

Важно: `of=/dev/sdX` — ЦЕЛОЕ устройство без номера раздела; образ
(гибридный ISO) сам создаёт свою разметку, содержимое флешки
затирается целиком.

- `status=progress` — показывает скорость и процент (иначе молчит);
- `bs=4M` — блок записи, ускоряет;
- `conv=fsync` — **дописывает всё содержимое на диск до выхода
  команды** — после dd с этим флагом отдельный sync не обязателен.

## sync: почему не глобальный и как по своему диску

Глобальный `sync` (без аргументов) синхронизирует ВСЕ буферы записи
системы и может ждать завершения чужих копирований (по Experience:
13-минутного копирования других файлов — и упирается в него).

GNU coreutils принимает файлы и устройства: `sync /dev/sdX` —
синхронизирует только указанный путь, не дожидаясь остального:

```sh
sync /dev/sdX        # только этот диск
```

В связке с dd удобнее полагаться на `conv=fsync`, а `sync /dev/sdX`
брать как привычку/подстраховку.

## Проверка результата

```sh
sudo fdisk -l /dev/sdX          # разметка должна стать от образа
sudo sh -c 'cmp -n $(stat -c%s /путь/к/образ.iso) /путь/к/образ.iso /dev/sdX' \
  && echo OK                     # побайтовое сравнение образа и диска
```

## Наш спасательный образ

ISO дистрибутива лежит в `iso/out/` репозитория wdistr (последний —
по времени). Спасательная флешка с ним: загрузка с неё даёт живую
среду с `/root/AGENTS.md` — агенту можно доверить диагностику,
если установленная система не поднимается. Перед записью свежих
правок — убедиться, что ISO собран ПОСЛЕДНИМ (правки в install/
попадают в образ только при сборке).
