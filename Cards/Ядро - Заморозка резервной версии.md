## Зачем

7.2.15 — последнее ядро ветки 7.2 (отмечено EOL). Пользователь хочет оставить его резервным на случай проблем в 7.3. Пакетов «с нумерацией» в Arch нет — версия `linux` в репозитории одна, при обновлении на 7.3 pacman удалит файлы 7.2.15. Поэтому ядро заморожено руками.

## Что где лежит (снято 2026-11-11 с работающей системы)

`~/kernel-pin/` (принадлежит пользователю, переживает `pacman -Scc` и обновления):

| Каталог | Содержимое | Назначение |
|---|---|---|
| `boot/` | `vmlinuz-linux` (17 МиБ), `initramfs-linux.img` (46 МиБ) | образ ядра и initramfs; fallback-файла нет — в `linux.preset` только пресет `default` |
| `modules/7.2.15-arch1-1/` | 528 МиБ | полный каталог модулей; имя с версией сохранено обязательно |
| `pkg/` | `linux-7.2.15…pkg.tar.zst` + `linux-headers-…` + подписи | архивный источник, если копии повредятся |

Пакеты взяты из `/var/cache/pacman/pkg` до воскресной очистки `sys-update` (скрипт после успеха гоняет `pacman -Scc`).

## Права

Файлы в `boot/` скопированы с правами `600` (как в исходном `/boot`). При раскладке в `/boot` для GRUB выставить `644`, иначе загрузчик не прочитает.

## Когда придёт 7.3 — план сборки резерва

1. Раскладка в `/boot` под отдельными именами, чтобы не конфликтовать с основным ядром:
   - `~/kernel-pin/boot/vmlinuz-linux` → `/boot/vmlinuz-linux-7215`
   - `~/kernel-pin/boot/initramfs-linux.img` → `/boot/initramfs-linux-7215.img`
   - права `644`
2. Модули: `/usr/lib/modules/7.2.15-arch1-1/` (pacman при обновлении на 7.3 удалит — восстановить из `~/kernel-pin/modules/`). Путь версионированный, с каталогом 7.3 не конфликтует.
3. Запись GRUB: свой `menuentry` в `/etc/grub.d/40_custom` (или `GRUB_DEFAULT` на неё) с `linux`/`initrd` на файлы из п.1. После — `sudo grub-mkconfig -o /boot/grub/grub.cfg`.
4. Заголовки (`linux-headers-7.2.15`) нужны, только если захочется компилировать модули под резервное ядро; для самой загрузки не требуются.

## Опыт 2026-11-11: разъезд sync-баз и защита wdistr-sys-update

Эксперименты с зеркалами привели к несогласованным базам pacman: `core.db` старая (openssl 3.6.5), `extra.db` свежая (55 пакетов требуют `libcrypto.so=4-64`) — `pacman -Syu` падал с «неразрешимыми зависимостями». Лечится принудительным `-Syy` со свежего зеркала (koyanet уже отдавал согласованную пару openssl 4.1.0 + linux 7.2.15).

Бояться при этом нечего — комментарий в `install/files/sys-update.sh` (коммит 0b8d78d): вопрос pacman «skip these packages?» — `noyes()`, дефолт N; `--noconfirm` отвечает дефолтом → транзакция падает целиком (`ALPM_ERR_UNSATISFIED_DEPS`), частичного обновления нет, `rc!=0` в лог, кэш не чистится, `OnFailure` повторяет через 4 часа.

Примечание про timeshift: таймер `wdistr-timeshift-check` щёлкает каждый час, `--check` создаёт снимок только по расписанию (daily/weekly) — «непосредственно перед обновлением» снимок не гарантируется. `Before=` в сервисе лишь расставляет очередь при одновременном старте.
