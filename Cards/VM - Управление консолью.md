Нужно, когда SSH в гостя недоступен, а посмотреть или выполнить что-то в
консоли надо. Основной случай — живая среда нашего ISO: у root там пустой
пароль, а sshd по умолчанию пустые пароли не пускает, так что SSH в лайв
не работает. Когда SSH доступен — предпочитать его: надёжнее и проще.

## Ввод команды

Скрипт `vm/vbox-console.py` переводит строку в сканкоды клавиатуры
(раскладка US) и отправляет их гостю через `VBoxManage controlvm ...
keyboardputscancode` — для гостя это эквивалент набора руками:

```bash
python3 vm/vbox-console.py wdistr-test "tail -40 /var/log/archinstall/install.log"
```

Перед командой автоматически шлётся Ctrl+C (прерывает выполняющуюся
команду и очищает строку ввода). Если сбрасывать не надо — отвечать на
запрос диалога — третий аргумент `noreset`:

```bash
python3 vm/vbox-console.py wdistr-test "y" noreset
```

Убедиться, что команда дошла и что именно выполняется, — по скриншоту
(см. ниже), выждав пару секунд после ввода.

## Скриншоты

Снимок экрана гостя одной командой с хоста:

```bash
VBoxManage controlvm wdistr-test screenshotpng /tmp/opencode/shot.png
```

Файл (PNG) затем читается инструментом просмотра изображений — он
показывает содержимое так же, как глазами. Удобный рабочий цикл:
ввод команды → `sleep N` → скриншот → чтение изображения → оценка.
Кадр фиксирует состояние экрана в момент вызова, поэтому после команды,
которая что-то печатает, обязательно пауза; долгие процессы (установка,
сборка) проверяются повторными скриншотами с интервалом в минуты.

## Ловушки (проверено на практике 2026-10-08)

- zsh в госте может перехватить опечатку вопросом вида
  `correct 'utail' to 'tail' [nyae]?` — тогда ввести `y` с `noreset`
  (без Ctrl+C, иначе ответ отменяется).
- Бесконечные команды (например, `ping` без `-c`) прерывать: скрипт и так
  шлёт Ctrl+C перед каждой новой командой, после чего строка ввода чистая.
- Консоль гостя в раскладке US — буквы, цифры, знаки препинания и основные
  спецсимволы (`/ - _ : " < > ? | { }`) поддерживаются; символы вне таблицы
  скрипт отвергнет с ошибкой, а не введёт мусор.
- После пересоздания VM меняется SSH-хост-ключ на хосте:
  `ssh-keygen -R '[127.0.0.1]:2223'` (иначе SSH в установленную систему
  будет ругаться на ключ).
- Ввод идёт в активную виртуальную консоль гостя (tty): команда попадёт
  туда, куда смотрит экран VM, — не запускать, если в консоли открыт
  диалог или меню.

## Инциденты

- **2026-10-15: окно VM упало, машина в состоянии aborted.**
  Симптом: `VBoxManage showvminfo` показывает `VMState="aborted"`,
  лог обрывается без штатного завершения. Причина — сегфолт самого
  процесса `VirtualBoxVM` на хосте, не сбой гостя:

  ```
  kernel: VirtualBoxVM[...]: segfault ... in libQt6Widgets.so.6.12.0
  systemd-coredump: Process (VirtualBoxVM) terminated abnormally with signal 11/SEGV
  ```

  Триггер: секундами ранее на хосте шла буря событий смены геометрии
  экранов (`Host-screen geometry changed`, `Screen count changed`,
  ресайзы рабочих областей до `0x0`) — подключение/переключение
  мониторов; ломается Qt-часть VirtualBox 7.2.20 на этой
  переконфигурации.

  Гость и его диск при этом НЕ пострадали (погиб только процесс
  отрисовки с гостевой памятью). Восстановление — просто запустить
  заново: `VBoxManage startvm wdistr-test`.

  Диагностика: `journalctl -b | grep -iE "virtualbox|segfault"` и
  `VBoxManage showvminfo <vm> | grep VMState`.

  **Лог самого сеанса VM лежит рядом с файлом `.vbox` на том диске,
  где живёт машина** (`/run/media/serg/EVO1TB/VirtualBox VMs/<vm>/Logs/VBox.log`),
  а не в `~/.config/VirtualBox/Logs` — там такого каталога может не
  быть.
