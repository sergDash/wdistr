date: 2026-10-08

Нужно, когда SSH в гостя недоступен, а посмотреть или выполнить что-то в
консоли надо. Основной случай — живая среда нашего ISO: у root там пустой
пароль, а sshd по умолчанию пустые пароли не пускает, так что SSH в лайв
не работает. Когда SSH доступен — предпочитать его: надёжнее и проще.

## Ввод команды

Скрипт `vm/vbox-console.py` переводит строку в сканкоды клавиатуры
(раскладка US) и отправляет их гостю через `VBoxManage controlvm ...
keyboardputscancode` — для гостя это эквивалент набора руками:

```bash
python3 vm/vbox-console.py wdistr-test "tail -40 /var/log/archinstall/install.log"
```

Перед командой автоматически шлётся Ctrl+C (прерывает выполняющуюся
команду и очищает строку ввода). Если сбрасывать не надо — отвечать на
запрос диалога — третий аргумент `noreset`:

```bash
python3 vm/vbox-console.py wdistr-test "y" noreset
```

Убедиться, что команда дошла и что именно выполняется, — по скриншоту
(см. ниже), выждав пару секунд после ввода.

## Скриншоты

Снимок экрана гостя одной командой с хоста:

```bash
VBoxManage controlvm wdistr-test screenshotpng /tmp/opencode/shot.png
```

Файл (PNG) затем читается инструментом просмотра изображений — он
показывает содержимое так же, как глазами. Удобный рабочий цикл:
ввод команды → `sleep N` → скриншот → чтение изображения → оценка.
Кадр фиксирует состояние экрана в момент вызова, поэтому после команды,
которая что-то печатает, обязательно пауза; долгие процессы (установка,
сборка) проверяются повторными скриншотами с интервалом в минуты.

## Ловушки (проверено на практике 2026-10-08)

- zsh в госте может перехватить опечатку вопросом вида
  `correct 'utail' to 'tail' [nyae]?` — тогда ввести `y` с `noreset`
  (без Ctrl+C, иначе ответ отменяется).
- Бесконечные команды (например, `ping` без `-c`) прерывать: скрипт и так
  шлёт Ctrl+C перед каждой новой командой, после чего строка ввода чистая.
- Консоль гостя в раскладке US — буквы, цифры, знаки препинания и основные
  спецсимволы (`/ - _ : " < > ? | { }`) поддерживаются; символы вне таблицы
  скрипт отвергнет с ошибкой, а не введёт мусор.
- После пересоздания VM меняется SSH-хост-ключ на хосте:
  `ssh-keygen -R '[127.0.0.1]:2223'` (иначе SSH в установленную систему
  будет ругаться на ключ).
- Ввод идёт в активную виртуальную консоль гостя (tty): команда попадёт
  туда, куда смотрит экран VM, — не запускать, если в консоли открыт
  диалог или меню.

## Инциденты

### Сегфолт VirtualBoxVM при пробуждении экрана хоста — ИЗВЕСТНЫЙ БАГ апстрима

Падение НЕ исследовать заново — это upstream-баг VirtualBox:
issue https://github.com/VirtualBox/virtualbox/issues/397
(«Segfault when turning screen off and on»; стек байт-в-байт наш,
как и у закрытых дублей #14, #121, #170, #244, #633). Наши случаи:
2026-10-15 10:36, 2026-10-17 09:35 — оба: процесс `VirtualBoxVM`
падает по signal 11, `VMState="aborted"`; гость и диск целы,
восстановление — перезапуск.

**Механизм** (разбор в issue, комментарии savek-cc и dr1fter):
в `UIDesktopWidgetWatchdog` при событии геометрии экрана хоста
создаётся невидимое QWidget-«полотно» (worker), которое максимизируют,
чтобы замерить рабочую область. `showMaximized()` накачивает очередь
событий Qt; во время шторма геометрий слот перезапускается, и
рекурсивный вызов удаляет worker, на котором ещё стоит внешний кадр
стека → use-after-free по vtable («segfault at 8»). Наш случай
17-го лог показал буквально: при пробуждении Screen 0 мгновенно
получил рабочую область 1120x700 вместо 2560x1400 (мониторы
перепутались местами), пошёл шторм, на последнем событии — смерть.
Шторм вызывает ЛЮБОЕ изменение рабочей области: пробуждение мониторов,
lock экрана, автоскрытие панели Cinnamon (у dr1fter — 100%
воспроизведение простым тогглом панели).

**Что НЕ помогает** (проверено в issue на идентичном стеке):
`QT_ACCESSIBILITY=0` — переменная Qt5, Qt6 её игнорирует;
галка Auto-resize Guest Display — это про разрешение гостя, а не
про watchdog хоста; галка Disable screen saver integration —
семантика обратная (перестаёт удерживать экран хоста от гашения).

**Рабочий обход** (подтверждён многими участниками issue):
`VBOX_DESKTOPWATCHDOGPOLICY_SYNTHTEST=Disabled` — отключает механизм
замеров через worker целиком (`isSynchTestRestricted()` → true).
Цена: возможно, менее точное размещение окон VirtualBox; гость не
затронут. Значение `ManagerOnly` НЕ брать (падения возвращались
через несколько дней, у `Disabled` — нет).

Пробный фикс Oracle (r173931, commit 700da74) есть в нашей 7.2.20
r175154, но неполный: он добавил `deleteLater()`, но вместе с
wildcard-disconnect(), снимающим внутренние destroyed()-связи Qt —
падения продолжаются (доклады и на 7.2.16). Issue открыта, назначена
разработчикам Oracle; ждать, обход — переменная окружения.

**Применение:** переменная должна быть в окружении процесса
`VirtualBoxVM`, а его порождает `VBoxSVC` — значит, и `VBoxSVC`
должен стартовать уже с ней. Способ — `/etc/environment`
(решение 2026-10-17, в дистрибутиве — строка custom_commands):
файл читает pam_env при любом входе — GUI-сессия, SSH, оболочки —
в отличие от `/etc/profile.d/`, который GUI-запуск VirtualBox
из меню не покрывает. Идемпотентная строка:
`grep -q '^VBOX_DESKTOPWATCHDOGPOLICY_SYNTHTEST=' /etc/environment || echo 'VBOX_DESKTOPWATCHDOGPOLICY_SYNTHTEST=Disabled' >> /etc/environment`
Важно: смена окружения действует только на НОВЫЕ процессы —
уже запущенная VM работает без защиты до перезапуска, и
VBoxSVC нужно перезапустить (перелогин или `pkill VBoxSVC`,
следующий вызов поднимет его с переменной).

**Диагностика:** `coredumpctl list | grep -i virtualbox` (даты
падений), `coredumpctl info <pid>` (стек). В логе сеанса VM последняя
строка — всегда ресайз экрана, на котором процесс умер.

**Лог сеанса VM лежит рядом с файлом `.vbox` на том диске, где живёт
машина** (`/run/media/serg/EVO1TB/VirtualBox VMs/<vm>/Logs/VBox.log`,
после падения — `VBox.log.1`), а не в `~/.config/VirtualBox/Logs`.
Временные метки в логе — uptime процесса, начало сеанса видно в шапке
(`Log opened ...` в UTC).
