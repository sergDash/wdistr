AUR-хелпер — программа, которая автоматизирует работу с Arch User
Repository: поиск, сборка PKGBUILD, установка, обновление. Pacman сам
по себе AUR не умеет — он работает только с готовыми пакетами из
репозиториев. Хелпер нужен, чтобы не клонировать и не собирать каждый
пакет вручную.

В wdistr используется **yay**: он собирается на первом запуске из AUR
же (`git clone` + `makepkg`), дальше ставит разрешённый список пакетов
и обслуживает еженедельное автообновление (`yay -Sua`).

## Сравнение yay и paru

По данным ArchWiki (обновлено 2026-07-13) оба входят в категорию
pacman-обёрток и по основным характеристикам равны:

| Свойство | yay | paru |
|---|---|---|
| Язык реализации | Go | Rust |
| Проверка PKGBUILD до сборки | да | да |
| Просмотр диффов | да | да |
| Надёжный парсер (RPC/.SRCINFO) | да | да |
| Решатель зависимостей | да | да |
| Split-пакеты | да | да |
| Дополнительно | — | сборка в чистом chroot, локальный репозиторий |
| Оболочки (completion) | bash, fish, zsh | bash, fish, zsh |
| Версия в AUR (2026-10) | 13.0.1 | 2.1.0 |
| Голосов в AUR | 2649 | 1260 |

Функционально для задач wdistr (установить фиксированный список, обновить
раз в неделю) оба равнозначны: команды те же (`-S`, `-Sua`, `--noconfirm`,
`--needed`), bootstrap — тот же (клон + makepkg).

## Где paru объективно шире

- **Сборка в чистом chroot** (через devtools, systemd-nspawn): пакет
  собирается в изолированной среде без доступа к сети и системе — так
  делают разработчики пакетов для official-репозиториев. Для AUR это
  плюс безопасности: PKGBUILD не увидит лишнего. Платёж — медленнее и
  нужны devtools.
- **Локальный репозиторий**: paru умеет складывать собранные пакеты в
  локальный pacman-репозиторий — удобно, если пакетов много и хочется
  отката. wdistr это не нужно: пакетов мало, список фиксированный.

## Что лучше для wdistr

Сейчас — yay, и менять нет причины: он работает, покрыт логами
first-boot и таймера, карточки и скрипты под него написаны. paru не
хуже по функциям, но переключение — это переписывание скриптов
(first-boot.sh, aur-update.sh) и проверка на чистой установке ради
отсутствующей у нас потребности (clean chroot, локальный репозиторий).

Если появится требование «собирать AUR-пакеты изолированно» (безопаснее
для пользователей дистрибутива) — paru станет естественным кандидатом.
Пока этого требования нет, выбор yay — не «лучший из возможных», а
«достаточный и уже проверенный».
