## Два каталога

Автозапуск по стандарту XDG (freedesktop.org Autostart Specification)
— это каталоги, из которых session-менеджер при входе пользователя
запускает программы:

| Каталог | Кого затрагивает | Кто сюда пишет |
|---|---|---|
| `/etc/xdg/autostart/*.desktop` | всех пользователей | пакеты, администратор |
| `~/.config/autostart/*.desktop` | только одного пользователя | сам пользователь или его настройки |

Пользовательский файл с тем же именем, что и системный, перекрывает
его: если `sticky.desktop` лежит в обоих каталогах, session
стартует пользовательский. Это штатный путь отключения системной
автозагрузки для конкретного пользователя без правки системных
файлов.

## Формат записей

Каждая запись — .desktop-файл со стандартными ключами:

```
[Desktop Entry]
Type=Application
Name=Sticky Notes
Exec=sticky --autostart
NoDisplay=true
X-GNOME-Autostart-Delay=5
```

Ключи, управляющие автозапуском:

| Ключ | Смысл |
|---|---|
| `Exec` | команда запуска; часто приложение получает флаг вроде `--autostart` |
| `Hidden=true` | не запускать и не показывать в списках настроек |
| `NoDisplay=true` | не показывать в списках настроек, но запускать |
| `OnlyShowIn=` | запускать/показывать только в перечисленных окружениях (GNOME, X-Cinnamon, …) |
| `NotShowIn=` | не запускать/показывать в перечисленных окружениях |
| `X-GNOME-Autostart-Delay` | задержка запуска в секундах |

`Hidden` и `NoDisplay` независимы: `Hidden=true` отключает и
запуск, и отображение; `NoDisplay=true` прячет запись только из
списка настроек — программа при входе стартует.

## Видимость в настройках рабочего стола

GUI-настройки автозапуска (например, «Настройки системы →
Автозагрузка» в Cinnamon, модуль `cs_startup.py`) читают оба
каталога — системные и пользовательские записи смешаны в одном
списке. Но записи фильтруются: показываются только те, у которых нет
`Hidden=true`, нет `NoDisplay=true` и `OnlyShowIn`/`NotShowIn`
допускают текущее окружение.

Практическое следствие: программа с `NoDisplay=true` в системном
файле запускается при каждом входе, но в списке настроек её нет —
управлять ей оттуда нельзя. Переключатель в настройках пишет
пользовательский файл (паттерн «перекрытия»), а не правит
системный.

## Приложение проверяет свою настройку при старте

Флаг `--autostart` в `Exec` — распространённый приём: приложение
при запуске с этим флагом проверяет собственную настройку
(обычно ключ dconf/GSettings) и молча завершается, если
автозапуск не включён.

Пример — Sticky Notes: пакет кладёт системный файл с
`Exec=sticky --autostart` и `NoDisplay=true`. При старте программа
читает ключ `org.x.sticky/autostart` (дефолт схемы — `false`) и
выходит, пока ключ не выставлен. Включение автозапуска — запись
ключа true (переключатель в настройках самой программы пишет тот же
ключ); сам .desktop-файл не меняется.

Преимущество схемы: настройка живёт в dconf, ею управляют штатные
средства (gsettings, dconf-editor, системные дефолты), а .desktop
остаётся неизменным частью пакета.

## Отключение автозапуска пакета

Пакет при установке кладёт свой .desktop в `/etc/xdg/autostart/`.
Отключить его для всех пользователей, переживая обновления пакета:

- **ключом dconf** — если приложение проверяет свою настройку
  (паттерн sticky выше): выставить ключ false в системном
  dconf-дефолте, приложение само не запустится;
- **файлом-перекрытием** — перезаписать файл пакета по тому же
  пути (`/etc/xdg/autostart/<имя>.desktop`) на версию с
  `Hidden=true`: session его видит, но игнорирует; при обновлении
  пакет файл восстановится — способ разовый;
- **хуком pacman** — при установке/обновлении пакета перезаписывать
  штатный файл на версию с `Hidden=true` (перезапись идемпотентна и
  переживает Upgrade; дописывать строку нельзя — дубли ключей в
  .desktop недопустимы).

Первые два пути не требуют root-прав в рантайме и работают на
любой системе; хук pacman — способ для Arch-подобных, где пакет
при обновлении перезаписывает свой файл.
