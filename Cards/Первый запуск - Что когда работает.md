Частое заблуждение: для инициализации системы нужен вход в графическую
сессию. На самом деле работа делится на две части.

## Без входа — при загрузке

Юнит `wdistr-first-boot.service` (системный, `WantedBy=multi-user.target`)
стартует сам при загрузке, ещё до гетера, и не требует сессии пользователя:

- обновление системы (`pacman -Syu`);
- подключение flathub и установка flatpak-программ;
- сборка и установка AUR-пакетов через yay;
- сборка opencode — идёт от имени первого пользователя через
  `sudo -u` с явным `HOME` (активная сессия для этого не нужна) и
  параллельно с AUR-пачкой (фон, дожидается в конце скрипта).

Проверка без входа — по SSH:

    systemctl is-active wdistr-first-boot   # activating / active / failed
    tail ~/install-log/first-boot.log       # rc-коды команд
    tail ~/install-log/opencode-build.log   # отдельный лог сборки opencode

## Что ждёт первого входа

- **Настройки Cinnamon** (тёмная тема Mint-Y-Dark-Aqua-10, шрифты Ubuntu,
  отключённые эффекты) — одноразовый скрипт `wdistr-cinnamon-defaults`
  из системного autostart (`/etc/xdg/autostart/`); управляется маркером
  `~/.config/wdistr/cinnamon-defaults-done`.
- **Пользовательский сервис syncthing** — включён симлинком в
  `default.target.wants`, но user-менеджер systemd запускается только с
  сессией (pam_systemd), поэтому демон поднимается при первом входе.

## Диагностика при поломке

Строгой режим: упавшая команда или неудачная сборка opencode делают код
юнита ненулевым → маркер `first-boot-done` не создаётся → при следующей
загрузке инициализация повторяется (шаги идемпотентны, см.
`Cards/Идемпотентность - Стабильность повторного запуска.md`).
Причина поломки — в конце `first-boot.log` (rc-коды) и в
`opencode-build.log`.

## Перезапуск без перезагрузки

Если инициализация висит (например, зависло скачивание бинарника AUR-пакета
— у скриптов сборки нет таймаута, соединение мертво, а CPU 0%), ждать
перезагрузки не нужно:

    sudo systemctl restart --no-block wdistr-first-boot

Флаг `--no-block` обязателен: без него `systemctl restart` для oneshot-юнита
синхронный — он ждёт, пока сервис дойдёт до финального состояния, а первый
запуск идёт часами, терминал «зависает» (по факту — блокируется ожиданием;
Ctrl+C оборвёт ожидание клиента, но сервис продолжит работать под init).
`--no-block` отправляет джоб в systemd и возвращает промпт сразу.

systemd убьёт все процессы в cgroup юнита (yay, makepkg, node) и запустит
скрипт заново. Условие `ConditionPathExists=!/var/lib/wdistr/first-boot-done`
по-прежнему проходит, пока маркер не создан. Шаги идемпотентны, повтор
безопасен: `pacman -Syu` быстро выйдет «делать больше нечего», flatpak
пропустит установленное, yay возьмёт собранное из кэша `~/.cache/yay`
и переидёт к незавершённому пакету.

Проверить после перезапуска:

    systemctl is-active wdistr-first-boot   # снова activating
    tail ~/install-log/first-boot.log       # новые строки после "== wdistr"
