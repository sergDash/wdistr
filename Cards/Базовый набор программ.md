## Служебный состав (необходим для работы рабочего стола)

Всё, без чего рабочий стол не поднимается или не выполняет базовых
задач. Сейчас в конфиге установщика (49 пакетов всего: 33 служебных
и 16 приложений из таблицы ниже).

1. `xorg-server` — X-сервер.
2. `xfce4` — рабочий стол (группа пакетов; временный до появления wdesktop).
3. `lightdm` — экран входа.
4. `lightdm-gtk-greeter` — оформление экрана входа.
5. `picom` — композитор; не запускается (работает встроенный xfwm4),
   остаётся для будущего wdesktop.
6. `virtualbox-guest-utils` — интеграция гостевой VM (мышь, экран).
7. `virtualbox` — для реальной машины (решение 2026-09-26).
8. `adwaita-cursors` — системный фолбэк курсоров (основной — McMojave,
   см. чек-лист «Комфортный рабочий стол»).
9. `papirus-icon-theme` — тема иконок по умолчанию; вносим явно, чтобы
   не зависеть от зависимостей xfce4 и пережить уход XFCE (решение
   2026-09-30).
10. `xorg-xsetroot` — установка фона/свойств X.
11. `xorg-setxkbmap` — смена раскладки из скрипта переключения (keyd).
12. `fish` — оболочка по умолчанию (root и пользователи).
13. `keyd` — раскладки клавиатуры и переключатель по Shift.
14. `nano` — простой редактор (в состав не входит автоматически).
15. `neovim` — редактор.
16. `vim` — редактор.
17. `pipewire` — звуковой сервер.
18. `pipewire-pulse` — совместимость с PulseAudio.
19. `pipewire-alsa` — совместимость с ALSA.
20. `wireplumber` — сессионный менеджер pipewire.
21. `xfce4-pulseaudio-plugin` — регулятор звука на панели.
22. `pavucontrol` — графический микшер звука.
23. `qpwgraph` — граф роутинга pipewire (инструмент настройки звука).
24. `network-manager-applet` — иконка сети в трее (nm-applet; из GNOME,
    у XFCE своего апплета нет).
25. `gnome-keyring` — хранилище ключей (нужен программе Authenticator).
26. `udisks2` — монтирование дисков без root по запросу программы
    (решение 2026-09-30; см. handbook «Автоподключение внешних дисков»).
27. `xdg-utils` — `xdg-open`: открытие файлов и ссылок (ни firefox, ни
    thunar его не тянут — решение 2026-09-30).
28. `inetutils` — команда `hostname` (в живой среде отсутствует).
29. `flatpak` — расширение охвата через flathub.
30. `ttf-dejavu` — базовые шрифты.
31. `ghostty` — терминал.
32. `htop` — монитор процессов.
33. `openssh` — доступ по SSH (в живой среде и для целевой системы).

Кандидаты №17–28 проверены установкой в тестовой VM — в конфиг пока не
перенесены; все найдены в официальных репозиториях (сверено 2026-10-08).
Кандидаты №35–39 разрешены для выбранного списка, с автообновлением
(механизм — при реализации).

Почему steam — flatpak (решение 2026-09-26): установка `steam` из
multilib интерактивно спрашивает 32-битный vulkan-драйвер под конкретное
железо (`lib32-vulkan-radeon` для AMD, `lib32-vulkan-intel` для Intel,
свой для NVIDIA) — ровно тот вопрос, который мы хотим убрать.
Flatpak-версия приносит свой runtime с mesa-драйверами и ставится без
единого вопроса. Multilib в дистрибутиве остаётся (wine, 32-битные
мелочи), сам steam — flatpak-путём после подключения flathub (задача
автоинициализации первого запуска).

Читки новостей — не нужны (FeedDeck, FeedFlow, Newsflash, RSS Guard,
Feeds): решение 2026-09-27.

## opencode — собственной сборки (решение 2026-09-26)

Не пакет из extra, а собственная сборка с патчами. База утверждена
2026-09-27: версия 1, самая последняя = v1.18.32; рецепт сборки —
`~/bin/opencode.fish <версия>` (тег + патчи `~/bin/opencode-{1,2,3}.patch`
+ bun build), при реализации рецепт переносится в репозиторий.
Сборка — задача этапа профиля (PKGBUILD → makepkg → pacman -U).
Готовые бинарники на хосте: `~/bin/opencode-1.18.32`, `opencode-1.18.33`.

## Открытые вопросы

- Механизм автообновления AUR и помощник — выбор при реализации.
- Автоинициализация первого запуска: состав (pacman -Syu, flathub),
  лог в `~/install-log/first-boot.log`; состав flatpak-программ —
  отдельно по списку пользователя.
- Граница «что входит в ISO, а что ставится потом» — состав базового
  набора требует согласования перед реализацией (см. AGENTS.md).
