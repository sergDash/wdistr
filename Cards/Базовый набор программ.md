Рабочий список состава дистрибутива. Источники проверены по базе extra
зеркала и API AUR (разведка 2026-09-27, сверено 2026-10-08). Решения
о включении — за пользователем. Какие программы реально стоят на хосте
разработки — `Cards/Хост - Установленные программы.md`.

Логика разделов: **служебный + временный состав дают минимум** — то, без
чего система не работает; **приложения — предпочтения пользователя**.

## Служебный состав (минимум системы)

1. `xorg-server` — X-сервер.

2. `lightdm` — экран входа.

3. `lightdm-gtk-greeter` — оформление экрана входа.

4. `picom` — композитор; не запускается (работает встроенный xfwm4),
   остаётся для будущего wdesktop.

5. `virtualbox-guest-utils` — интеграция гостевой VM (мышь, экран).

6. `virtualbox` — для реальной машины (решение 2026-09-26).

7. `adwaita-cursors` — системный фолбэк курсоров (основной — McMojave,
   см. чек-лист «Комфортный рабочий стол»).

8. `papirus-icon-theme` — тема иконок по умолчанию; вносим явно, чтобы
   не зависеть от зависимостей xfce4 и пережить уход XFCE (решение
   2026-09-30).

9. `xorg-xsetroot` — установка фона/свойств X.

10. `xorg-setxkbmap` — смена раскладки из скрипта переключения (keyd).

11. `pipewire` — звуковой сервер.

12. `pipewire-pulse` — совместимость с PulseAudio.

13. `pipewire-alsa` — совместимость с ALSA.

14. `wireplumber` — сессионный менеджер pipewire.

15. `pavucontrol` — графический микшер звука.

16. `network-manager-applet` — иконка сети в трее (nm-applet; из GNOME,
    у XFCE своего апплета нет).

17. `nm-connection-editor` — GUI-редактор подключений NetworkManager;
    приезжает зависимостью `network-manager-applet`, отдельно в конфиг не вносим.

18. `blueman` — менеджер Bluetooth; демон `bluez` и `bluez-libs`
    приезжают зависимостями (в конфиг вносим только blueman).

19. `gnome-keyring` — хранилище ключей (нужен программе Authenticator).

20. `udisks2` — монтирование дисков без root по запросу программы
    (решение 2026-09-30; см. handbook «Автоподключение внешних дисков»).

21. `xdg-utils` — `xdg-open`: открытие файлов и ссылок (ни firefox, ни
    thunar его не тянут — решение 2026-09-30).

22. `ttf-dejavu` — базовые шрифты.

23. `openssh` — доступ по SSH (в живой среде и для целевой системы).
24. `base-devel` — инструменты сборки (makepkg — нужен для AUR-пакетов,
    решение 2026-10-08).
25. `git` — клонирование AUR-репозиториев (установка yay) и прочие
    задачи.

## Временный состав (уйдёт вместе с XFCE)

- `xfce4` — рабочий стол (группа пакетов); временный до появления
  wdesktop.
- `xfce4-pulseaudio-plugin` — регулятор звука на панели XFCE.

## Приложения

(решение 2026-10-09; прежде flatpak ставился выше AUR — решение
2026-09-27, иерархия уточнена 2026-10-08, — но опыт показал: темы
приложений в песочнице слетают на светлые, а AUR-пакеты живут в
системе и слушают её настройки; в flatpak остаётся steam). Установщик:
`конфиг` — пакеты из `install/archinstall-config.json`; `скрипт` —

Почему steam — flatpak (решение 2026-09-26): установка `steam` из
multilib интерактивно спрашивает 32-битный vulkan-драйвер под конкретное
железо (`lib32-vulkan-radeon` для AMD, `lib32-vulkan-intel` для Intel,
свой для NVIDIA) — ровно тот вопрос, который мы хотим убрать.
Flatpak-версия приносит свой runtime с mesa-драйверами и ставится без
единого вопроса. Multilib в дистрибутиве остаётся (wine, 32-битные
мелочи), сам steam — flatpak-путём после подключения flathub (задача
автоинициализации первого запуска).

Почему приоритет поменян на AUR (решение 2026-10-09): в песочнице
приложения не видят системных настроек GTK — темы слетают на светлые,
приходится бороться разрешениями и порталами; AUR-пакеты ставятся в
систему, читают темы и иконки напрямую, а у нас уже есть системные
дефолты dconf (Adwaita-dark) и `/etc/gtk-3.0/settings.ini`, которые их
держат тёмными. Издержки AUR (чужой PKGBUILD исполняется при сборке,
сборка требует времени) приняты осознанно: список разрешённых пакетов
закрыт, ставятся только они.

Читки новостей — не нужны (FeedDeck, FeedFlow, Newsflash, RSS Guard,
Feeds): решение 2026-09-27.

## opencode — собственной сборки (решение 2026-09-26)

Не пакет из extra, а собственная сборка с патчами. База утверждена
2026-09-27: версия 1, самая последняя = v1.18.32; рецепт сборки —
`~/bin/opencode.fish <версия>` (тег + патчи `~/bin/opencode-{1,2,3}.patch`
+ bun build), при реализации рецепт переносится в репозиторий.
Сборка — задача этапа профиля (PKGBUILD → makepkg → pacman -U).
Готовые бинарники на хосте: `~/bin/opencode-1.18.32`, `opencode-1.18.33`.
