Сборка ISO идёт прямо на этой машине — она работает под нашим
дистрибутивом (Arch): `pacman` и `mkarchiso` доступны, репозиторий
лежит локально, агент работает в той же системе, где идёт сборка.
Работа сводится к одной команде mkarchiso: без выделенной VM, без
передачи профиля тарболом, без SSH в гость.

Прежняя схема (Linux Mint + Arch-гость VirtualBox `wdistr-build`)
сохранена как историческая — `Cards/Сборочная виртуальная машина.md`;
она пригодится, если понадобится собирать на машине без Arch. Сам
конвейер (состав профиля, ловушки mkarchiso, тест) — в
`Cards/Сборка ISO archiso.md`.

Статус: карточка составлена 2026-10-12; пакеты раздела «Пакеты
сборки» установлены на этой машине тем же днём и внесены в базовый
состав дистрибутива (строки 71–73 `Cards/Базовый набор программ.md`)
— на свежей установке они уже стоят.

## Пакеты сборки

Проверено 2026-10-12. Уже были: `git`, `python3`, `curl`, `7z`, `tar`,
`ssh`, `sshpass`, `xz`, `zstd`, VirtualBox 7.2.20 (пакеты `virtualbox`,
`virtualbox-host-dkms`, `dkms`). Доустановлены 2026-10-12 (и внесены в
`packages[]` конфига установки):

```sh
sudo pacman -S archiso qemu-img linux-headers
```

- `archiso` — даёт `mkarchiso`; pacman сам дотянет зависимости, среди
  которых `squashfs-tools` (mksquashfs), `dosfstools` (mkfs.fat),
  `mtools` (mmd/mcopy), `libisoburn`, `erofs-utils`,
  `arch-install-scripts` — ровно то, что mkarchiso проверяет у сборщика
  перед стартом.
- `qemu-img` — разбор дисков VM (`handbook/Извлечение файлов с диска
  VirtualBox.md`); к самой сборке отношения не имеет.
- `linux-headers` — заголовки текущего ядра, под которые
  `virtualbox-host-dkms` собирает модуль `vboxdrv`. До установки
  заголовков модуля нет (проверено 2026-10-12: `VBoxManage` отвечает
  «vboxdrv kernel module is not loaded»), и тестовая VM не стартует.
  При установке `linux-headers` pacman-хук dkms собрал модуль сам
  (`dkms install vboxhost/7.2.20_OSE`, 2026-10-12), `vboxconfig` не
  понадобился. Модуль (вместе с `vboxnetadp`, `vboxnetflt`) грузится при
  старте системы из `/usr/lib/modules-load.d/virtualbox-host-dkms.conf`;
  вручную без перезагрузки — `sudo modprobe vboxdrv`. Проверки:
  `modinfo vboxdrv` (собран), `lsmod | grep vboxdrv` (загружен).

## Безпарольная сборка

Сборка идёт от root, поэтому обычный `sudo mkarchiso` спрашивает
пароль, а запуск из агента — polkit-диалог. Решение (2026-10-12) —
обёртка `wdistr-build-iso` (исходник — `install/files/wdistr-build-iso`:
чистка `work/` + запуск mkarchiso с фиксированными путями) и одно
NOPASSWD-правило на неё. Отдельные безпарольные `rm` или `mkarchiso`
не давали: `rm` — дыра, два правила хрупки; «две команды» сводятся к
одной обёртке.

**В дистрибутив не поставляется** (решение 2026-10-12: собирать
дистрибутив внутри дистрибутива не нужно) — обёртка и правило живут
только на этой рабочей машине. Первый запуск дистрибутива при этом
оставляет прежнее правило `wheel-pacman` (нужно yay в фоне).

Установка на машине вручную (блок для копирования):

```sh
sudo install -m 755 install/files/wdistr-build-iso /usr/local/bin/wdistr-build-iso
echo '%wheel ALL=(ALL) NOPASSWD: /usr/local/bin/wdistr-build-iso' | sudo tee /etc/sudoers.d/wheel-build >/dev/null
```

Проверка: `sudo -l | grep build` показывает право, а запуск
`sudo wdistr-build-iso <репозиторий>` идёт без вопросов (лог сборки —
в терминал или через `> build.log 2>&1` со стороны вызывающего).

## Сборка

Обёрткой — одна команда из любого каталога (см. «Безпарольная
сборка»):

```sh
sudo wdistr-build-iso /home/serg/src/wdistr
```

То же самое вручную, шаг за шагом (если обёртки нет):

```sh
cd /home/serg/src/wdistr
sudo rm -rf work
sudo mkarchiso -v -w work -o iso/out iso
```

Что означают каталоги:

- `work/` — рабочий каталог mkarchiso: маркеры выполненных шагов и весь
  промежуточный объём. Перед КАЖДОЙ сборкой удаляется — иначе маркеры
  прошлой (или прерванной) сборки молча пропускают шаги, и mkarchiso
  завершается «успехом», не создав ISO (случай 2026-09-26; детали —
  `Cards/Сборка ISO archiso.md`).
- `iso/out/` — куда mkarchiso кладёт готовый ISO; этот же каталог
  читает тестовый стенд (`vm/create-test-vm.sh` берёт последний
  `iso/out/wdistr-*.iso`).
- Профиль передаётся явным путём (`iso` от корня репозитория), запуск —
  строго из корня: так ошибка «не та текущая папка» невозможна
  (`handbook/Проблема - mkarchiso не находит профиль.md`).

Выходные файлы датированы (`wdistr-ГГГГ.ММ.ДД-x86_64.iso`, ~1.5 ГиБ
каждый), конфликта имён со старыми нет — чистить `iso/out` вручную по
мере накопления.

## Ловушки рабочей системы

- **Параллельный pacman.** mkarchiso держит блокировки pacman, пока
  идёт сборка; запуск `pacman -Syu` / `pacman -S ...` в это время ведёт
  к конкуренции за `db.lck`, шаг initcpios падает, и сборка выдаёт
  битый ISO (случай 2026-09-26). Пока сборка идёт, на машине ничего не
  ставим. Раньше правило касалось только сборочной VM; теперь сборка
  идёт на рабочей системе — и действует на неё.
- **Не выключать и не усыплять машину** на время сборки: work/ и
  монтирования остаются в состоянии обрыва, поможет только чистка.
- `work/` принадлежит root — чистить через `sudo`.

Полезное: pacstrap использует кэш pacman самой системы
(`/var/cache/pacman/pkg`), поэтому повторные сборки переиспользуют уже
качаные пакеты.

## Что от прежней схемы больше не нужно

- Передача профиля тарболом (`iso-profile.tgz` + `python3 -m
  http.server`) — профиль `iso/` используется на месте.
- Обратный канал выноса ISO (проброс `isoout` 9999→8000) и SSH в
  сборочную VM (2222→22) — ISO сразу появляется в `iso/out/`.
- Скачивание стокового ISO Arch (`vm/archlinux-*.iso`) — требовалось
  только для установки сборочной VM.
- `vm/create-build-vm.sh` — скрипт прежней схемы, оставлен в
  репозитории как исторический.

## Тест собранного ISO

Собранный ISO проверяется в VirtualBox, как и раньше:

```sh
bash vm/create-test-vm.sh
```

- Предпосылка — модуль `vboxdrv` (раздел «Пакеты сборки»); без него
  `VBoxManage` откажется запускать VM.
- Живая среда в текстовой консоли: ввод команд и снимки экрана без SSH —
  `Cards/VM - Управление консолью.md`.
- SSH в установленную систему — порт 2223, ключ `~/.ssh/wdistr_build_vm`:
  его публичная часть вшита в дистрибутив через custom_commands, поэтому
  целевая система принимает подключение сразу.

## Где что лежит

- `iso/out/wdistr-*.iso` — выходные файлы сборки (в git не попадают).
- `work/` в корне репозитория — рабочий каталог mkarchiso (в git не
  попадает, удаляется перед каждой сборкой).
- `Cards/Сборочная виртуальная машина.md` — историческая схема сборки.
