**Статус: историческая (с 2026-10-12).** Рабочая машина перешла на наш
дистрибутив (Arch), ISO собирается прямо на ней — см.
`Cards/Сборочная реальная машина.md`. Карточка сохранена как описание
прежней схемы (Linux Mint + Arch-гость VirtualBox) на случай, если
понадобится собирать на машине без Arch. Факты внутри — по состоянию на
2026-10-08.

Сборочная VM `wdistr-build` — Arch-гость VirtualBox, в котором собирался
наш ISO. Нужна была потому, что на хосте (Linux Mint) нет `pacman` и
`mkarchiso`, а стоковый ISO Arch собирает проблемы меньше, чем своя
машина с нужными пакетами. Карточка покрывает весь путь: создание →
установка → подготовка → работа → пересоздание. Сам конвейер сборки ISO —
отдельно, в `Cards/Сборка ISO archiso.md`.

## Что требуется

- **VirtualBox** (на хосте — 7.2.14 с Oracle Extension Pack).
- **Внешний диск EVO1TB подмонтирован** в `/media/serg/EVO1TB`. На нём лежат
  конфиги всех VM (файл `defaultMachineFolder` в настройках VirtualBox
  указывает на `/media/serg/EVO1TB/VirtualBox VMs`). Если диск не подмонтирован
  — VirtualBox не увидит сборочную машину (покажет «inaccessible»), хотя сами
  данные не теряются.
- **Место на диске**: виртуальный диск до 64 ГБ (создаётся в `vm/` на корневом
  разделе хоста, занимает по факту сколько занято в госте) плюс стоковый ISO
  Arch ≈ 1.6 ГБ в `vm/`.
- **Утилиты хоста**: `git`, `python3`, `curl`, `7z`, `unsquashfs`, `tar`,
  `ssh`, `qemu-img` — всё входит в Linux Mint 22.3 или ставится штатно
  (проверено 2026-10-08; пакеты-источники: `7zip`, `squashfs-tools`,
  `qemu-utils`, `openssh-client`).
- **SSH-ключ хоста** `~/.ssh/wdistr_build_vm` — им агент подключается к гостю.
  Если его нет, создать:
  `ssh-keygen -t ed25519 -f ~/.ssh/wdistr_build_vm -C wdistr-build@wdistr-host`
- **`sshpass`** (на хосте есть, 1.09) — подключение с паролем `123` до
  закладки ключа, см. чек-лист подготовки.

## Создание

Один скрипт из корня репозитория:

```bash
bash vm/create-build-vm.sh
```

Что делает:

1. Скачивает стоковый ISO Arch в `vm/` (если его нет) и один раз проверяет
   контрольную сумму по `vm/sha256sums.txt` (файл сумм в git, сам ISO — нет).
2. Регистрирует VM `wdistr-build`: 8 ГБ оперативки, 4 ядра, виртуальный диск
   64 ГБ (`vm/wdistr-build.vdi`, в git не попадает), загрузка с DVD, потом с диска.
3. Сразу прописывает **постоянные** пробросы портов: `ssh` 2222→22 и `isoout`
   9999→8000. Они живут в файле конфигурации VM и переживают выключение —
   ничего при каждом запуске пересоздавать не нужно.

Если VM уже существует, скрипт откажется и подскажет команду пересоздания.

## Установка Arch в окне VM

После создания: `VBoxManage startvm wdistr-build` — в окне загрузится
стоковый ISO. **После загрузки живой среды выполни команду `archinstall`.**
Установка вручную, по пачке критичных ответов ниже; это делается один раз
за жизнь VM (при пересоздании — заново).

Критичные ответы (не пропускать — без них система выходит нерабочей):

1. Mirrors and repositories → Select regions → **Russia**. Back.
2. Disk Configuration → Partitioning → **Use a best-effort default
   layout** → **ext4** → **No** (home). Back.
3. Authentication → User account → Add a user → **user / 123** →
   **Yes** (sudo). Confirm and exit. Back.
4. Profile → Type → **Server** → **sshd** (профиль ставит openssh и
   включает службу). Back.
5. Network configuration → **Use Network Manager** — без него в
   установленной системе не поднимется даже интерфейс (случай
   2026-10-08: нет сети — не работает pacman). Back.
6. **Install** → Yes.
7. **Reboot**.

После Reboot VM снова стартует с ISO — в меню загрузки выбрать
**Boot existing OS** (загрузка уже установленной системы).

Прочие ответы (язык, локаль, часовой пояс, hostname) не критичны —
поправим после.

## Подготовка после первой загрузки

От человека — войти в систему (**user / 123**) и сказать агенту.
Всё остальное делает агент по SSH: первые входы — с паролем `123`
(`sshpass -p 123 ssh -p 2222 user@127.0.0.1`; `sshpass` на хосте есть),
после закладки ключа — по ключу `~/.ssh/wdistr_build_vm`.

Что делает агент:

1. Обновление системы: `pacman -Syu`.
2. Пакеты для сборки: `pacman -S archiso sudo` (`openssh` и `sshd` уже
   поставлены профилем Server). Версия `archiso` в репозитории может
   опережать профиль (91 против снятого с 90) — это нормально: по
   changelog изменения 90→91 профиль не затрагивают (проверено
   2026-10-08), см. `Cards/Сборка ISO archiso.md`.
3. Закладка ключа хоста в `authorized_keys` (от `user`):

   ```sh
   mkdir -p ~/.ssh && chmod 700 ~/.ssh
   echo '<содержимое ~/.ssh/wdistr_build_vm.pub>' >> ~/.ssh/authorized_keys
   chmod 600 ~/.ssh/authorized_keys
   ```

   Подключение переключается на ключ.
4. Sudo без пароля для `user` (от root):

   ```sh
   echo 'user ALL=(ALL) NOPASSWD: ALL' > /etc/sudoers.d/user
   chmod 440 /etc/sudoers.d/user
   ```

5. Проверки: подключение по ключу, `systemctl is-enabled sshd`,
   `pacman -Q archiso`.

Целевое состояние — как на прежней сборочной (проверено 2026-10-08), на
нём держится вся работа агента. Пересозданная 2026-10-08 машина
подготовлена по этому списку и проверена: сеть, sshd, archiso 91,
sudo NOPASSWD, вход по ключу.

**GUI не ставить (решение 2026-10-08).** На прежней сборочной стояли
xfce4, lightdm, picom, nm-applet, blueman — всё ставилось только под
визуальные тесты тем и иконок; темы выбраны и зафиксированы (Papirus,
Adwaita-dark, см. `handbook/Чек-лист - Комфортный рабочий стол.md`).
Для сборки ISO графическая оболочка не нужна — после пересоздания машина
остаётся консольной.

## Работа

- **Запуск**: `VBoxManage startvm wdistr-build`. SSH по порту 2222 работает
  сразу (правила постоянные, см. «Создание»).
- **Подключение агента**: `ssh -i ~/.ssh/wdistr_build_vm -p 2222 user@127.0.0.1`;
  до закладки ключа — с паролем `123` через `sshpass` (см. чек-лист).
- **Выключение**: `VBoxManage controlvm wdistr-build acpipowerbutton`
  (аналог кнопки питания). Если гость не среагировал — `VBoxManage controlvm
  wdistr-build poweroff` (грубый сброс, данные тестовые; во время идущей
  сборки так **не** делать — останется мусорный `work/`, см.
  `Cards/Сборка ISO archiso.md`).
- Выключать VM можно в любой момент, когда сборка не идёт: система, логи и
  выходные файлы живут на виртуальном диске и переживают выключение.

## Пересоздание

Плановое пересоздание решено 2026-10-08: прежняя машина накопила GUI под
тесты тем (больше не нужен), после пересоздания она остаётся консольной.
Следующий шаг после пересоздания — сборка ISO и установка дистрибутива в
тестовую VM (другая машина).

Пересоздавать сколько угодно раз — это штатная работа, согласования не
требует. Порядок:

1. Выключить VM (см. выше).
2. `VBoxManage unregistervm wdistr-build --delete` — удаляет конфиг и
   виртуальный диск. После этого проверить, не остался ли `vm/wdistr-build.vdi`
   (в git не попадает, ~50 ГБ), и при необходимости удалить вручную.
3. **Стереть запись host key нового гостя** из `~/.ssh/known_hosts` — иначе
   SSH откажется подключаться с предупреждением о смене ключа:
   `ssh-keygen -R '[127.0.0.1]:2222'`
4. `bash vm/create-build-vm.sh` — создать заново, затем установка Arch и
   чек-лист подготовки.

## Где что лежит

- `vm/create-build-vm.sh` — создание (в git).
- `vm/archlinux-*.iso`, `vm/sha256sums.txt` — стоковый ISO и его суммы
  (ISO в git не попадает, суммы — входят).
- `vm/wdistr-build.vdi` — виртуальный диск сборочной (в git не попадает).
- `/media/serg/EVO1TB/VirtualBox VMs/wdistr-build/wdistr-build.vbox` —
  конфиг VM и правила пробросов (внешний диск, в git не попадает).
- `~/.ssh/wdistr_build_vm` — ключ хоста для доступа к гостю (вне репозитория).

## Известные особенности

- **Конфиги VM на внешнем диске.** Пока EVO1TB подмонтирован — всё видно.
  Отключили диск — VirtualBox покажет машину «inaccessible»: это не поломка,
  подключить диск обратно. VDI-диск при этом лежит на корневом разделе хоста
  (`vm/`), так что доступность зависит от обоих мест.
- **Host key меняется при каждой переустановке гостя** — запись в
  `known_hosts` чистить (пункт 3 пересоздания).
- Перед сборкой `work/` и `out/` в госте удаляются обязательно — иначе
  маркеры старой сборки пропускают шаги и ISO не создаётся; и параллельно
  на сборочной не запускать `pacman`. Обе ловушки описаны в
  `Cards/Сборка ISO archiso.md`.
