Полный проверенный конвейер: от профиля до тестируемого ISO (2026-09-26).
С 2026-10-12 сборка идёт прямо на рабочей машине, без выделенной VM —
см. `Cards/Сборочная реальная машина.md`.

## Где что живёт

- Профиль — `iso/` в репозитории (снят с пакета archiso-90 из extra;
  версию профиля держать синхронизированной с установленным archiso).
- Сборка — на этой же машине (она работает под wdistr, Arch); пакеты
  сборки и команда запуска — `Cards/Сборочная реальная машина.md`.
- Выходные файлы mkarchiso создаются в `out` **относительно текущей папки
  запуска** (запуск из `~` → `~/out`), не профиля — поэтому в команде
  ниже каталог выхода задан явно (`-o iso/out`).
- Тестовый стенд — `vm/create-test-vm.sh` (VM `wdistr-test` со свежим
  `iso/out/wdistr-*.iso`).

## Файлы, которые кладутся в профиль перед сборкой

Оба тяжёлые и в git не версионируются (лежат только в рабочем дереве;
в `.gitignore` есть их пути), поэтому после clone/pull их нужно положить
заново:

1. **Бинарник opencode** (~180 МБ) — единственный способ, как opencode
   попадает в систему: сборка на первом запуске отключена (решение
   2026-10-13), бинарник уезжает в живую среду готовым, а оттуда
   `setup` копирует его в целевую.

   - Собрать opencode (рецепт — `install/files/opencode/opencode.fish`,
     версия обязательным аргументом: `opencode.fish 1.19.0+`; дефолта
     нет — свежая версия на момент установки неизвестна).
   - Скопировать бинарник в профиль:
     `cp ~/bin/opencode-<версия> <репо>/iso/airootfs/usr/local/bin/`
   - Симлинк `opencode -> opencode-<версия>` уже стоит в репозитории
     (крошечный файл, версионируется). При смене версии — обновить его
     и строку `file_permissions` в `iso/profiledef.sh`: archiso
     копирует airootfs с `--no-preserve=mode`, и без этой строки
     бинарник приходит в живую среду без +x (опыт 2026-10-12).

2. **Шрифты Windows** (342 МиБ, 143 файла):

   ```bash
   cp -a install/files/winfonts iso/airootfs/usr/share/fonts/winfonts
   ```

   Исходник — `install/files/winfonts/` (см.
   `Cards/Шрифты - Windows-шрифты.md`).

Важно про границу живой и установленной систем: файлы из `airootfs`
попадают **только в живую среду** — archinstall содержимое airootfs в
целевую систему не копирует (проверено 2026-10-12: в свежей
установке `/usr/local/bin/opencode` отсутствует). Раньше карточка
утверждала обратное — это было неверно. Доставка в целевую сделана
копированием из живой среды: `setup` после archinstall монтирует
целевую и копирует opencode, шрифты Windows, курсоры McMojave, тему
дистрибутива, карты раскладок keyd и консольный шрифт с vconsole.conf
(решение 2026-10-12 — вместо base64 в custom_commands: сотни мегабайт
в JSON не влезают, а тяжёлое копируется файлами). В base64 остались
только мелкие конфиги и скрипты.

## Профиль — на месте

Репозиторий локален, профиль `iso/` используется напрямую — никакой
передачи не нужно. Устарело с 2026-10-12 (прежняя VM-схема): тарбол
`iso-profile.tgz` + `python3 -m http.server` и обратный канал выноса ISO
через проброс `isoout` (9999→8000) / scp по SSH (порт 2222).

## Сборка

```sh
cd /home/serg/src/wdistr
sudo rm -rf work
sudo mkarchiso -v -w work -o iso/out iso   # путь к профилю явный, см. handbook/Проблема - mkarchiso не находит профиль.md
```

Полный разбор команды (каталоги, ловушки рабочей системы) — в
`Cards/Сборочная реальная машина.md`.

## Готовый ISO

ISO появляется в `iso/out/` (путь задан флагом `-o`), имя датированное —
`wdistr-ГГГГ.ММ.ДД-x86_64.iso`. Оттуда его берёт тестовый стенд
(`vm/create-test-vm.sh` читает последний `iso/out/wdistr-*.iso`).
Старые ISO в этом каталоге копятся — чистить вручную.

## Проверка содержимого ISO без загрузки

Основной путь — чек-лист скриптом (создан 2026-10-15):

```bash
iso/check-iso.sh                 # свежий iso/out/wdistr-*.iso
iso/check-iso.sh путь/к/файлу.iso
```

Скрипт извлекает squashfs из ISO (xorriso, без монтирования и root),
распаковывает только нужные файлы во временный каталог и снимает его
через `trap` — хвостов в /tmp не остаётся (ручные распаковки раньше
застревали: unsquashfs копирует права каталогов из архива, `r-x`
не разбирался `rm`, опыт 2026-10-15). Чек-лист: остановка зеркал в
setup-continue, регион `## wdistr` и состав зеркал, сверенный с
`mirrors.txt`, dispatcher с chmod 755, минус на ExecStop, noto-fonts-cjk,
timezone, opencode (симлинк → бинарник 755), 143 winfonts. Код выхода 1
при любом провале. Новая существенная правка образа — новая проверка
в скрипте.

Вручную (как скрипт внутри, для разбора конкретного файла):

```bash
xorriso -indev <iso> -osirrox on -extract /arch/x86_64/airootfs.sfs /tmp/x.sfs
unsquashfs -d /tmp/x/ex /tmp/x.sfs root/wdistr etc/hostname
```

## Тест

```bash
bash vm/create-test-vm.sh          # пересоздание: VBoxManage unregistervm wdistr-test --delete
```

В госте: `sh /root/wdistr/go.sh --dry-run`, затем `sh /root/wdistr/go.sh`.

**Память тестовой VM: 8 ГБ МАЛО** (случай 2026-10-09): первый запуск
(AUR-сборки librepcb, jan, localsend) даёт пик памяти ~6.8 ГБ, и OOM
killer убивает `wdistr-first-boot` (юнит `failed`, повтор при загрузке
помогает двигаться дальше, но бесконечные повторы не заменяют память).
Для теста поднимать до 16 ГБ: `VBoxManage modifyvm wdistr-test --memory
16384` (на выключенной машине). На реальном железе с большой RAM
проблемы нет.

- Выключение тестовой VM командой `controlvm ... acpipowerbutton` может
  не сработать (2 случая 2026-09-26, XFCE-гость) — тогда `controlvm ... poweroff`
  (данные тестовые, допустимо).

## Известные особенности

- В живой среде нет команды `hostname` — проверять `cat /etc/hostname`.
- В текстовой консоли живой среды мышь захватывается (интеграция неактивна
  до X) — в окно не кликать.
- Для пересборки после правок профиля — просто повторить сборку (профиль
  берётся на месте, тарбол и передача больше не нужны). Изменения вида
  «добавить пакет в живую среду» — `iso/packages.x86_64`;
  изменения содержимого установленной системы — конфиг в `install/`.
- Имена файлов в `iso/airootfs/usr/local/bin/` не должны совпадать с
  coreutils (`install` сломал две сборки — см.
  `handbook/Проблема - Имя install ломает сборку ISO.md`; команда
  переименована в `setup`).

## Перед сборкой — перегенерировать доставку

Если правились файлы в `install/files/` или `mirrors.txt` — пересобрать
команды доставки:

```bash
python3 install/regen-custom-commands.py   # сам синхронизирует конфиг с профилем
```

Иначе изменения не доедут до устанавливаемой системы (airootfs настраивает
только живую среду, целевая система получает настройки через custom_commands).

## Перед КАЖДОЙ пересборкой — удалять work

Внутри `work/` mkarchiso хранит маркеры «шаг уже выполнен». Если каталог
остался от прошлой (или прерванной) сборки, повторный запуск **молча
пропускает все шаги и завершается с кодом 0, не создав ISO** — выглядит
как мгновенное «падение» после `Validating options... Done!`
(случай 2026-09-26). Каталог `out` чистить не обязательно: имена ISO
датированные, конфликта со старыми нет. Безопасный шаблон запуска:

```sh
cd /home/serg/src/wdistr
sudo rm -rf work
sudo mkarchiso -v -w work -o iso/out iso 2>&1 | tee ~/build.log
```

(в пайпе `tee` код возврата mkarchiso теряется — ориентироваться на
вывод и на появившийся ISO в `iso/out/`).

Проверка, что сборка реально идёт: в логе через ~10 секунд должны
появиться строки `checking keyring...` / загрузки пакетов, а не только
`Done!` валидации.

## Во время сборки — НЕ запускать pacman

Сборка держит блокировки pacman. Параллельный запуск `pacman -S ...`
(случай 2026-09-26: пользователь ставил htop) ведёт к конкуренции за
`db.lck`: шаг `Updating linux initcpios` падает с
`Pacman is already running ... lock never exited`, initramfs не создаётся —
и сборка доходит до конца, выдав **битый ISO** с ошибкой
`install: cannot stat '.../initramfs-*.img'`.

Правило: пока идёт mkarchiso, на машине ничего не ставим. С 2026-10-12
это касается уже рабочей системы, а не отдельной сборочной VM (тогда
конкурировал только пользователь VM). Всё докачиваем после (в том числе
htop и прочие личные утилиты). При таком отказе — чистка `work/` и
полная пересборка.
