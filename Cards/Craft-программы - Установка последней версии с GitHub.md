## Итог (решение 2026-10-16)

В дистрибутив идут **AUR-пакеты** `photocraft`, `vectorcraft`,
`wordcraft`, `gridcraft` — добавлены в AUR-список `first-boot.sh`
(перед beekeeper-studio, чтобы тяжёлая yarn-сборка осталась последней).
Обоснование: по философии проекта «родной пакет > AUR > flatpak» AUR
выше bundle; обновления приходят штатным механизмом `yay -Sua`
(`aur-update.sh` + таймер), скрипт с GitHub API не нужен.

Отдельные .desktop-файлы НЕ создаются: AUR-пакеты ставят свои
(`/usr/share/applications/ai.storyteller.*.desktop`). Категории в них
смысловые: WordCraft и GridCraft — Office, PhotoCraft и VectorCraft —
Graphics (рядом с GIMP и Inkscape). Перекрытие своих файлами отклонено:
pacman при обновлении пакета конфликтует на чужой файл с тем же именем.

Оставшаяся часть карточки (bundle через GitHub API) — историческая
справка на случай, если AUR-пакеты обянутся или захотим быструю
установку без компиляции. Следующий раздел — про релизы GitHub.

Четыре приложения ArtCraft (студия storytold) в репозиториях Arch
отсутствуют; в дистрибутив они входят через AUR-список first-boot
(решение выше). Оставшееся тело карточки — справка об альтернативном
пути (flatpak-bundle с релизов GitHub), сохранена на случай, если
AUR-пакеты обянутся.

## Формат распространения

Каждый релиз содержит набор одинаковых по структуре ассетов:

- `<имя>-<версия>-linux-x86_64.flatpak` — **нужен нам**: установка
  одной командой без сборки и без репозитория.
- `linux-aarch64.*` — то же для ARM64 (на нашей машине не применяется).
- `.AppImage` — в проекте зарезервирован под менеджер обновлений
  (решение по источникам программ), вручную не ставится.
- `.deb`, `.rpm` — для Debian/Fedora, на Arch не применимы.
- `.tar.gz` — дерево `bin/` + `share/`, монтируется руками в `/opt`;
  без преимуществ перед bundle.

На Flathub приложений нет (политика по AI-коду, см. upstream
issue #173) — официальный канал распространения этих программ это
релизы GitHub.

## Получение последней версии: GitHub API

Адрес одного запроса:

```
GET https://api.github.com/repos/storytold/<имя>/releases/latest
```

Ответ (JSON) содержит:

- `tag_name` — версия, например `v0.9.0` (сравнение с установленной
  версией — способ узнать, есть ли обновление);
- `assets[]` — список файлов релиза; нужен тот, у кого `name`
  заканчивается на `-linux-x86_64.flatpak`, его адрес —
  `browser_download_url` (прямая ссылка на скачивание, работает без
  токена).

Ограничения API без токена: 60 запросов в час с одного IP. Четыре
запроса на прогон — запас большой, но при часовой периодичности
автообновления предел будет исчерпан; для частых прогонов нужен токен
(`Authorization: Bearer <token>`) либо редкий запуск. Ответ с кодом
403 и заголовком `X-RateLimit-Remaining: 0` означает исчерпание лимита.

Скелет получения ссылки (python3 есть в базовом составе):

```sh
repo=photocraft
curl -s "https://api.github.com/repos/storytold/$repo/releases/latest" \
  | python3 -c "
import json, sys
d = json.load(sys.stdin)
url = next(a['browser_download_url'] for a in d['assets']
           if a['name'].endswith('-linux-x86_64.flatpak'))
print(url)
"
```

## Установка командой

Скачивание и установка (путь из upstream README программ):

```sh
repo=photocraft
url=<ссылка из предыдущего шага>
curl -L -o "/tmp/$repo.flatpak" "$url"
flatpak install --user -y "/tmp/$repo.flatpak"
```

Нюансы, которые надо учесть при реализации:

- **Рантайм.** Bundle зависит от `org.freedesktop.Platform` — он
  скачивается с Flathub. Flathub подключается на первом запуске
  дистрибутива (`first-boot.sh`), так что на целевой системе рантайм
  доступен; в чистой системе без подключённого Flathub flatpak сам
  предложит установить зависимость, а без сети установка не пройдёт.
- **`--user` или системная установка.** `--user` — как в README
  программ (ставится в `~/.local/share/flatpak`, доступно одному
  пользователю). Системная установка (от root, без `--user`) — как
  остальные flatpak в дистрибутиве (`first-boot.sh` ставит их от root
  с `--noninteractive -y`). Выбор зависит от того, куда встроится
  реализация: в первый запуск — системная, в пользовательский
  скрипт — `--user`.
- **Повторная установка — это обновление.** Тот же файл поверх
  установленного заменяет версию, команда идемпотентна.

Проверка установленного:

```sh
flatpak info ai.storyteller.photocraft        # версия установленного
flatpak list --app --columns=application,version | grep ai.storyteller
```

## Где это может жить в проекте

Варианты ниже — для bundle-пути (историческая справка; реализован
AUR-путь, см. «Итог»):

1. **Отдельный скрипт в `install/files/`** — доставляется
   custom_commands, как остальные файлы; после правки папки —
   `python3 install/regen-custom-commands.py`.
2. **Первый запуск (`install/files/first-boot.sh`)** — программы
   появляются в составе сразу после установки; конвейер там уже
   работает с flatpak (remote-add + install из списка).
3. **Ручная команда** — один блок для копирования, без автоматизации.

Обновление: bundle не умеет обновляться сам (в отличие от
flathub-пакетов — у них есть `flatpak-update.timer` в проекте).
Автообновление = периодический прогон «API → скачать → install»;
если автопрогоны планируются часто — учесть лимит API из раздела выше.

## Альтернатива: AUR

В AUR уже есть пакеты всех четырёх программ: `photocraft`,
`vectorcraft`, `wordcraft`, `gridcraft` (варианты `-bin` — сборка из
бинарника релиза, `-git` — из исходников). Это важно для выбора пути:

- По философии проекта источник — «родной пакет > AUR > flatpak»
  (карточка `Базовый набор программ.md`), то есть AUR выше
  flatpak-bundle.
- AUR-пакеты обновляет уже существующий механизм автообновления
  (`install/files/aur-update.sh`, `yay -Sua` по разрешённому списку) —
  обновления приходят сами, без скрипта с GitHub API.
- Bundle, наоборот, даёт установку без компиляции и не зависит от
  состояния PKGBUILD в AUR.

Выбор сделан 2026-10-16 в пользу AUR (см. «Итог»): обновления без
своего скрипта, категории .desktop от пакетов, соответствие
философии источников.
