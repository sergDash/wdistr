# AGENTS.md

## Состояние проекта

- Репозиторий создан 2026-09-25, git инициализирован. Кода и инструментов сборки пока нет. Цель — собственный дистрибутив на базе Arch Linux.
- Хост разработки — Linux Mint 22.3: `pacman` и `mkarchiso` там недоступны, VirtualBox 7.2.14 установлен. Значит сборка ISO возможна только в Arch-окружении, а не на хосте.
- Роли: пользователь принимает решения, агент выполняет работу. Коммиты агент делает сам, без отдельного запроса.
- Команды build/test/lint пока не выдумывать: их место — здесь, после появления реального инструментария.

## Принятые решения (2026-09-25)

- Основа — стандартный Arch Linux: переупаковка и докрутка. Своего репозитория пакетов не делаем.
- Целевая философия — «поставил и работает» (в духе fish): минимальная настройка, минимализм, без стремления улучшать всё подряд.
- Отношение к Arch — «на самотек», но некоторые компоненты намеренно патчим и замораживаем. Подход должен быть осилим одним человеком + ИИ.
- Оболочка по умолчанию — fish.
- Визуал — тёмная тема в стиле Windows 10. Свой рабочий стол — отдельный проект; его код и конфиги сюда не переносить.
- Направление своего рабочего стола (для отдельного проекта): оконный менеджер без настроек, вшитые тёмные цвета, квадратные окна с контрастной рамкой, панель задач с треем, «Пуск» для выбора программ; цель — стабильность без свистоперделок.
- Временный рабочий стол до появления своего — XFCE; дополнительно keyd (раскладки клавиатуры, переключатель раскладки на любой клавише). Для XFCE выбран композитор xfwm4 (встроенный) — picom установлен, но не запускается (решение 2026-09-26, см. handbook); picom останется для будущего своего рабочего стола.
- Программы — минимальный базовый набор из репозиториев Arch; расширение охвата через Flatpak; AppImage — только через менеджер обновлений, не обновлять вручную.
- В базовый набор входит `virtualbox-guest-utils` (интеграция мыши/клавиатуры в тестах — решение 2026-09-26) и `virtualbox` (для реальной машины — решение 2026-09-26); состав набора открыт, пополняем по ходу.
- multilib — включить (нужен для steam; решение 2026-09-26). Нюанс: конфиг archinstall multilib включать не умеет — правка pacman.conf живой среды через профиль ISO и установленной системы, задача этапа профиля.
- AUR — разрешён для выбранного списка пакетов, с автообновлением (решение 2026-09-26). Список разрешённых и механизм автообновления — `install/Базовый набор программ.md`; реализация — отдельной задачей (помощник ставится из AUR же).
- opencode — в дистрибутив собственной сборки, с патчами (не пакет из extra; решение 2026-09-26). База для сборки — вопрос открыт: локальный исходник (v1.18.32 с правками) против пакета 2.0.18 из extra.
- Идея менеджера «всё в одном» (как в Zorin): общий верхний слой абстракций над установкой программ, пользователь только ставит галочки; источники AppImage — GitHub API, официальные сайты. Пока это идея, не решение: реализацию прорабатывать отдельно.
- Установка — только с собственного ISO (профиль archiso). Собранные ISO и любые эксперименты тестируются в VirtualBox.
- Установка — минимум вопросов: ответы преднастроены, пользователь не отвечает на «1000 дурацких вопросов» (ценность «поставил и работает» распространяется и на установщик; эталон ответов — `handbook/Archinstall - Ответы для нашей системы.md`).
- Сборочная среда — Arch-гость VirtualBox на хосте разработки; гость пересоздаётся сколько угодно раз (создание/пересоздание/проверка VM — обычная работа, не требует согласования). Сборочная VM доступна агенту по SSH: `ssh -i ~/.ssh/wdistr_build_vm -p 2222 user@127.0.0.1` (проброс порта — сессионное правило `VBoxManage controlvm ... natpf1`, при выключении VM пересоздать постоянно через `VBoxManage modifyvm wdistr-build --natpf1 "ssh,tcp,,2222,,22"`).
- Репозиторий должен стать инструкцией и основой для сборки других вариантов систем: структура профиля и скриптов — обобщённая, не захардкоженная под один дистрибутив (цель варианта Б — полной автоматизации).
- Знания по проекту фиксируются в двух местах: `handbook/` — инструкции «как сделать», `Cards/` — маленькие справки-карточки. Вести их обязательно. Каждая столкнутая сложность (что сломалось, в чём причина, как вышли) — статья в `handbook/`; перечень таких статей — прямая цель проекта.
- Форматы handbook: статьи-объяснения — как что устроено; нерешённые проблемы — статьи с префиксом `Проблема - ` (симптом, что известно, что пробовали, статус «не решено», непроверенные идеи). Рецепты и команды включать только реально применимые в описанной ситуации.
- Часть компонентов намеренно «заморожена» от улучшений: не модернизировать и не переписывать без явного запроса. Список конкретных позиций появится здесь по ходу работы.
- Первый запуск — автоинициализация (решение 2026-09-26): `pacman -Syu` (базы всех репозиториев, включая multilib) + подключение flathub; лог каждого запуска — `~/install-log/first-boot.log` (читаемо пользователем и агентом), туда же планируется AGENTS.md дистрибутива для сценария самопроверки opencode'ом. Список программ из flatpak — отдельно, по списку пользователя (читки новостей не нужны, многое есть в репозиториях Arch).
- Идея (2026-09-26): opencode в дистрибутиве как средство самопроверки — после инициализации открыть папку, запустить opencode, сказать агенту «проверь»: он сам разбирается по AGENTS.md, что проверять. Тогда дистрибутиву нужен свой AGENTS.md с инструкциями проверки.
- Идея (2026-09-26): тяжёлые и «вопросительные» программы (steam и подобные) ставить через flatpak — там нет интерактивных вопросов вроде выбора vulkan-драйвера.
- Пока не решено и требует согласования перед реализацией: состав базового набора программ (граница «что входит в ISO, а что ставится потом»; рабочий список — `install/Базовый набор программ.md`), реализация multilib и автообновления AUR, база и версия собственной сборки opencode, выбор менеджера обновлений AppImage, реализация менеджера «всё в одном».

## Соглашения

- Все создаваемые тексты в репозитории (документация, комментарии, заметки, сообщения об изменениях) — на русском языке.
- Глобальные правила `~/.agents/rules/*.md` (стиль кода, русская формулировка, справочник, карточки знаний) подгружаются в каждую сессию автоматически — здесь не дублируются.
- Межсессионная память — `.agents/memory/*.md`, заметки о знаниях и прогрессе пользователя по проекту — `.agents/rules/user.md`. Оба шаблона подключены через `instructions` в `~/.config/opencode/opencode.json`.
